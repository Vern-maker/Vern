# 会议纪要与行动闭环

先阅读 [共同工作规则](../../references/working-principles.md)，使用 [纪要模板](references/deliverable.md)。需要跟踪任务时读取 [统一任务字段](../../references/task-data-contract.md)。

## 输入与范围
使用所给转写/笔记、会议日期、参会人和当前背景。只有音频而无可用转写工具时说明输入限制，先整理已有文本，不能虚构听写内容。

## 工作方法
1. 识别主题、重要数字、客户要求、产品反馈、风险和未决问题。对金额、单位、名称和说话者归属进行交叉核对。
2. 将已决定、建议讨论、未形成结论分开；发言中的“考虑”“可能”不能写成已批准事项。
3. 提取行动、主责、截止日、依赖、验收标准和来源定位。原文未指定责任人/期限时标待确认，建议值另列。
4. 相对日期仅在会议日期明确时转换为绝对日期，并保留原话；“下周五”等有歧义表达列待确认。
5. 同一行动重复出现时合并并保留来源，冲突数字列出各版本与出处，不自行选择。任务沿用已有 ID；新任务可用同一会议 ID 加序号。

## 交付检查
先写会议结论，再写决策与行动，最后列待确认。避免逐句转述。默认交付可分发文本；只有用户明确授权发送或同步时才操作外部系统，不把生成纪要视为发送许可。
